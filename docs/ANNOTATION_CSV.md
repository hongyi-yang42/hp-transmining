# The trilingual annotation CSV

The one annotation document. Each row is a German prepositional-phrase
occurrence with its English and Chinese **retrieval context** — the
machine-aligned anchor sentence(s) expanded by one neighbouring sentence
on each side, so counterparts the strict alignment left just outside the
anchor group are still visible; the annotator fills the remaining
columns in a single pass. The returned file is the German review **and**
the EN/ZH counterpart annotation, and it is the only input the
eligible-pool build reads (`scripts/build_eligible_pool.py
--review-csv`).

- Generated by: `scripts/build_annotation_csv.py` (from the machine
  master, Ch.1–17).
- Encoding: UTF-8 with BOM (`utf-8-sig`) — opens correctly in Excel,
  including the Chinese text. Do not "repair" the BOM if your editor
  asks.
- Validated on return by: `scripts/validate_annotation_csv.py` — run it
  before handing the file back; it reports aggregate rule violations
  only. Every machine column is re-derived from the master and compared
  cell by cell, so an edited context or German sentence is rejected even
  when `row_hash` is untouched.

## Columns

### Machine columns — read-only, do not edit

| column | meaning |
|---|---|
| `id` | Stable row identity. Quote it in any question about a row. |
| `chapter` | Chapter number (1–17). |
| `form` | `contracted` (e.g. *im Haus*) or `uncontracted` (e.g. *in dem Haus*). |
| `german_pp` | The extracted German PP (preposition through noun). |
| `german_head_lemma` | The machine's head-noun lemma. Correct it in `de_corrected_lemma` if wrong. |
| `german_sentence` | The full German sentence for context. |
| `english_context` | English retrieval context: the aligned anchor sentence(s) plus one neighbour on each side, space-joined. |
| `chinese_context` | Chinese retrieval context: same construction. |
| `row_hash` | Integrity check value. **Ignore it; never edit it.** |

### German review columns

| column | how to fill |
|---|---|
| `de_valid` | `include` if the row is a genuine definite German PP of the kind the study targets; `exclude` otherwise (relative-pronoun or demonstrative readings, parse artifacts, wrong span). Every row must get one of the two values. |
| `de_corrected_lemma` | Blank = the machine lemma (`german_head_lemma`) is correct. Non-blank = the correct head-noun lemma. |
| `de_exclusion_reason` | Required when `de_valid = exclude` (vocabulary below); must be blank otherwise. |
| `de_notes` | Free text; anything the exclusion vocabulary doesn't capture. |

Exclusion reasons: `not_target_pp` (not a PP of the target kind),
`not_definite` (the PP is structurally outside the definiteness
contrast), `extraction_error` (wrong head, wrong span, parser error),
`duplicate` (same occurrence as another row — note its `id`),
`other` (always explain in `de_notes`).

### English / Chinese marking columns

Fill for every row you marked `de_valid = include` (rows you exclude
are skipped on both sides):

| column | how to fill |
|---|---|
| `en_counterpart` / `zh_counterpart` | The span in `english_context` / `chinese_context` that translates the German PP. Copy the text exactly. |
| `en_form` / `zh_form` | The form category of that span (vocabularies below). |
| `en_alignment_confidence` / `zh_alignment_confidence` | **Your** confidence that the provided context is the right counterpart context: `high`, `medium`, `low`, or `not_aligned` (the sentence shown is simply not the translation of this German sentence). This is a human judgment — it has nothing to do with any machine score. |
| `en_notes` / `zh_notes` | Free text (e.g. why a span was hard to delimit). |

**No counterpart in the context?** Two different situations share this
appearance — separate them explicitly:

- The context **is** the right translation of this German sentence
  (alignment confidence `high`/`medium`/`low`) and genuinely contains no
  counterpart: set the form to `omitted`, span blank. This is a true
  omission by the translator.
- The context is **not** the translation of this German sentence: set
  the alignment confidence to `not_aligned`. If you also see no
  counterpart, use form `omitted` + confidence `not_aligned` — together
  they mean "retrieval failed, this row needs repair", **not** that the
  translator omitted anything.

**Unsure what the counterpart is (but the context is right)?** Set the
form to `uncertain` (span optional) and explain in the notes column.

`en_form` vocabulary: `definite`, `bare_singular`, `demonstrative`,
`indefinite`, `possessive`, `pronoun`, `proper_name`, `other`,
`omitted`, `uncertain`.

`zh_form` vocabulary: `bare`, `demonstrative`, `numeral_classifier`,
`possessive`, `pronoun`, `proper_name`, `other`, `omitted`,
`uncertain`.

## Coupling rules (the validator enforces these)

- A counterpart span requires a form; a form requires a span — except
  `omitted` (form only, span blank) and `uncertain` (form only, span
  optional, notes required).
- A set form requires a non-blank alignment confidence on the same side
  (this keeps `omitted` interpretable: `omitted` + `high`/`medium`/`low`
  = true omission; `omitted` + `not_aligned` = retrieval failure).
- `de_valid = exclude` requires a valid exclusion reason; `include`
  requires the reason blank.
- Any decision other than `include`/`exclude` (including blank) means
  the review is not finished — the file will be rejected until every
  row is decided.

## After annotation

1. `uv run python scripts/validate_annotation_csv.py <returned.csv>
   --master-tsv data/derived/step4/full_novel_annotation_master.tsv`
   — must report 0 violations.
2. `uv run python scripts/build_eligible_pool.py --extraction-dir
   data/extracted/full_novel --master-tsv
   data/derived/step4/full_novel_annotation_master.tsv --review-csv
   <returned.csv> --out-dir data/derived/eligible_pool` — builds the
   formal pool once, from the completed review.
